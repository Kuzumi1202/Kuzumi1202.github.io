面试考点：C# 基础

发表于2025-10-08|更新于2026-11-13|游戏开发
|浏览量:

面向对象

面向对象三大特征

  • 继承：提高代码重用度
  • 封装：增强数据安全性
  • 多态：不同环境下，同名方法

值类型、引用类型与结构体

  • 值类型变量保存值，赋值通常复制值；引用类型变量保存对象引用，赋值复制引用。
  • 值类型包括数值、布尔、字符、枚举和结构体；引用类型包括类、接口、委托和数组，string 也是引用类型。
  • 存储位置取决于上下文，不能简单记为“值类型在栈、引用类型在堆”。例如类中的结构体字段随对象存储，装箱后的值位于托管堆。
  • 结构体不能继承其他类或结构体，但可以实现接口；类支持单一基类继承。
  • 结构体可以通过 new 初始化。C# 10 起支持显式无参构造函数，使用时需确认 Unity 支持的语言版本。
  • 结构体不能声明为 static，但可以包含静态成员。

密封类和普通类有什么区别

  • 密封类不能被继承，密封方法不能被重写

接口与抽象类

  • 两者都不能直接实例化。抽象类可以包含字段、构造函数和已实现的方法。
  • 类只能继承一个基类，但可以实现多个接口；接口也可以继承多个接口。
  • 接口用于约定能力，抽象类用于共享状态和实现。现代 C# 支持部分默认接口实现，需确认目标运行时支持情况。

重载和重写的区别

  • 重载在同类中，重写在子类中
  • 定义方法不同，重载方法名相同，参数列表不同；重写方法名、参数列表都相同
  • 调用方式不同，重载使用相同对象以不同参数调用，重写用不同对象以相同参数调用
  • 多态时机不同，重载编译时多态，重写运行时多态

数据结构

ArrayList 和 List 的区别

  • ArrayList 不带有泛型，数据类型丢失
  • List 带有泛型，数据类型不丢失
  • ArrayList 存储值类型时需要装箱，取回时通常需要拆箱；List 存储 T 类型的值时通常避免这一过程

链表和数组的区别

内存布局

  • 数组：顺序存储，占用一块连续的内存，大小固定，扩容成本大。
  • 链表：链式存储，非连续的，并且多一个指针，不存在大小限制，天然支持动态扩容。

性能

  • 随机查找
    • 数组可以支持随机访问，O(1)的时间复杂度
    • 链表需要按顺序逐个访问，O(n)的时间复杂度
  • 插入删除
    • 数组时间复杂度 O(n)
    • 已知目标节点时，链表插入或删除为 O(1)；若先按位置查找，则为 O(n)

列表和字典的底层实现

List

  • 底层实现：动态泛型可扩容数组
  • 考题：现在 List 容量为 4 个元素，现在要插入一个新元素进去，底层会发生什么。
    • 容量不足时才扩容
    • 扩容时分配新数组并复制内容；旧数组在不可达后等待 GC

Dictionary

  • 底层实现：
    • Buckets 哈希桶
    • entrys 数组用来存储数据
    • 从 entrys 中删除的数据，构成一个 freelist 空闲数据链表；当插入时，优先插入数据到这个里面去。
  • 考题：现在 Dictionary 容量有 4 个元素，现在插入 1 个新元素进去，此时底层会发生什么。
    • 容量不足时才扩容
    • 扩容时分配新数组并复制内容；旧数组在不可达后等待 GC
    • hash 找 buckets 索引
    • 将新数据挂载到 buckets 索引处的单链表中
  • 考题：现在 Dictionary 容量有 4 个元素，现在删除 1 个已有元素，此时底层会发生什么。
    • 查找到目标元素
    • 修改链表指针指向
    • 将移除的元素加入 freelist
  • 关于 Hash
    • Hash 函数算法
      • Hash 桶算法：首先将 key 通过 hash 函数生成 hashcode，然后和 hash 桶的数量进行取余，结果用于确认将这个值存储到哪个桶中
      • 平方取中法：取 keyword 平方后中间几位作为散列地址
      • 随机数法：选一随机函数，取 keyword 的随机值作为散列数据，经常用于 keyword 长度不同的场合
    • Hash 碰撞算法
      • 拉链法（开散列）：在发生哈希冲突的位置，生成一个链表，用来存储哈希冲突的元素
      • 开放地址法（闭散列）：发生哈希冲突的位置开始，依此向后探测，直到找到下一个空位置位置。
      • 再哈希法

设计模式

单例模式

  • 概念：构造函数私有，外部无法直接创建
  • 应用场景：管理器

观察者模式

  • 概念：通过委托实现 1 对多的订阅关系
  • 应用场景：事件派发

工厂模式

  • 概念：根据不同条件需求，构建不同的实例
  • 应用场景：英雄、怪物、npc

策略模式

  • 概念：将可替换的算法或行为封装到统一接口后，由调用方选择策略
  • 应用场景：游戏设置界面，根据 GPU 性能，批量设置群组显示效果

命令模式

  • 概念：有执行队列需求，且支持撤销需求
  • 应用场景：FPS 输入模块，需要存储输入指令的时候

其他

访问修饰符与常见关键字

关键字 含义
public 不限制访问
private 限于声明类型内部
internal 限于当前程序集
protected 限于声明类型及其派生类型
protected internal 当前程序集或派生类型可访问
private protected 当前程序集内的派生类型可访问

abstract 声明抽象类型或成员；virtual 允许重写；override 重写继承的虚成员；sealed 阻止继承或继续重写；new 隐藏继承成员，不能代替重写。

static 成员属于类型；const 表示编译期常量；实例 readonly 字段仅能在声明处或所属类型的实例构造函数中赋值。delegate 声明委托类型，event 声明事件。

装箱拆箱

  • 装箱：装箱就是将值类型转换为引用类型
  • 拆箱：引用类型转化为值类型
  • 装箱性能问题：每次装箱都要在堆里面 new 一个新对象，当量大时会影响程序效率

C#垃圾回收机制

  • .NET 分代回收概念（不直接代表所有 Unity 后端）
    • 0 代：新分配对象通常进入第 0 代
    • 1 代：0 代垃圾回收中没有被回收的对象
    • 2 代：1 代垃圾回收后仍然没有回收的对象
    • GC 的压缩行为取决于运行时和堆类型，不能保证不存在碎片。Unity 的 GC 实现应按引擎版本和后端单独确认。
