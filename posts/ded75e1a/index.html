TCP 连接与关闭

三次握手

  1. 客户端发送 SYN，请求建立连接。
  2. 服务端返回 SYN + ACK，确认请求并发送自己的初始序号。
  3. 客户端返回 ACK，确认服务端的初始序号，连接建立。

三次握手让双方确认彼此的收发能力，并同步初始序号。

四次挥手

以客户端主动关闭为例，服务端也可以主动关闭连接：

  1. 客户端发送 FIN，表示不再发送数据。
  2. 服务端返回 ACK，确认客户端的关闭请求；此时仍可发送剩余数据。
  3. 服务端发送 FIN，表示自己也不再发送数据。
  4. 客户端返回 ACK，进入 TIME_WAIT；服务端收到 ACK 后关闭连接。

TCP 的两个传输方向可以独立关闭，因此通常需要分别确认。ACK 与 FIN 也可能合并，关闭连接不一定恰好使用四个报文段。

TIME_WAIT 与 2MSL

主动关闭方通常等待 2MSL 后才释放连接，主要用于在最后一个 ACK 丢失时回应重传的 FIN，并降低旧连接延迟报文对后续连接的影响。

MSL 是最大报文段生存时间。2MSL 的实际时长取决于协议栈实现，不能统一记为 4 分钟。

TCP 与 UDP

对比项 TCP UDP
连接 面向连接 无连接
传输语义 有序、可靠的字节流 数据报，不保证到达、顺序或去重
消息边界 不保留应用消息边界 保留数据报边界
通信方式 一条连接对应两个端点 可用于单播、多播和广播，支持情况取决于网络
首部 最小 20 字节 8 字节

TCP 的可靠传输依赖序号、确认、重传等机制；流量控制保护接收方，拥塞控制调节网络负载。连接失败时，应用仍需处理错误与重连。

消息边界：粘包与拆包

TCP 传输字节流，一次发送不对应一次接收。接收方可能一次读到多条消息，也可能分多次才读完一条消息。

常见处理方式：

  • 长度前缀：在消息头记录正文长度，接收方累计字节后按长度解析。
  • 分隔符：以换行等符号划分消息，并处理正文中的转义。
  • 固定长度：适用于消息尺寸固定的协议。

使用长度前缀时，需要校验长度上限，保留未读完整的数据，并循环解析已收齐的消息。

相关基础：进程与线程

  • 进程通常拥有独立的虚拟地址空间，是操作系统分配和隔离资源的重要单位。
  • 线程是操作系统调度执行的基本单位之一。同一进程内的线程共享地址空间，但各自拥有栈和执行上下文。
  • 线程共享数据时需要考虑同步、互斥与竞态；进程也可以通过共享内存等 IPC 机制交换数据。
  • 进程之间的隔离通常更强，创建和切换开销则取决于系统与负载，不能仅凭多进程或多线程判断稳定性。
