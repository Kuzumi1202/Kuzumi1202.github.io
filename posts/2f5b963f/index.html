MonoBehaviour（生命周期）

概述

MonoBehaviour 是 Unity 中常用的组件脚本基类，提供了一系列在特定时间自动调用的生命周期方法。

常见生命周期回调

阶段 方法 调用时机 用途说明 执行频率
初始化阶段 Awake() 脚本实例被创建时立即调用 初始化变量、获取组件引用 仅一次
OnEnable() 脚本组件启用时调用 注册事件、启动协程 每次启用时
Start() 在所有 Awake() 调用后，第一次 Update 前 初始化依赖其他对象的内容 仅一次
物理更新阶段 FixedUpdate() 固定时间间隔调用 物理相关计算、刚体操作 固定频率
OnTriggerXXX() 触发器碰撞发生时 处理触发器交互 事件触发时
OnCollisionXXX() 碰撞体碰撞发生时 处理物理碰撞 事件触发时
游戏逻辑阶段 Update() 每帧调用 游戏核心逻辑、输入处理 每帧
LateUpdate() 所有 Update 执行后调用 摄像机跟随、后期处理 每帧
场景渲染阶段 OnBecameVisible() 物体进入摄像机视野 性能优化相关处理 状态改变时
OnBecameInvisible() 物体离开摄像机视野 禁用不必要的更新 状态改变时
OnPreRender() 摄像机开始渲染场景前 渲染前准备工作 每帧渲染前
OnPostRender() 摄像机完成渲染场景后 渲染后处理工作 每帧渲染后
UI阶段 OnGUI() 渲染和处理 GUI 事件时 IMGUI 系统绘制界面 每帧多次
暂停与退出 OnApplicationPause() 应用暂停或恢复时 保存游戏状态等 状态改变时
OnDisable() 脚本组件禁用时 清理资源、取消事件注册 每次禁用时
OnDestroy() 脚本实例被销毁时 最终清理工作 仅一次
OnApplicationQuit() 应用退出前调用 保存数据、释放资源 仅一次

执行顺序示意图

使用注意

  1. 执行顺序范围：图示仅表达常见阶段；一帧可能执行零次或多次 FixedUpdate。不同对象之间的同类回调顺序默认不保证，运行时创建和激活对象也需单独考虑。
  2. 渲染回调：可见性可能受多个相机及编辑器 Scene 视图影响；OnPreRender、OnPostRender 主要用于内置渲染管线，SRP 需使用对应回调。
  3. 内存管理：在 OnDestroy 中清理非托管资源
  4. 事件安全：在 OnDisable 中取消事件订阅避免内存泄漏

碰撞器和触发器

  • 物体发生碰撞的必要条件
    • 都带有碰撞器，运动的带有刚体
  • CharacterController 使用 OnControllerColliderHit 处理移动碰撞，不应直接套用 Rigidbody 的碰撞回调条件。

伪多线程

协程

  • 底层通过迭代器状态机保存执行位置，由 Unity 调度恢复。
  • GameObject 被 SetActive(false) 或宿主被销毁时协程停止；仅禁用 MonoBehaviour 不会自动停止协程
  • 协程通常在主线程分段执行，不会自动创建工作线程；耗时同步操作仍会阻塞主线程
  • yield return 0 和 yield return 10 没有区别，都是下帧执行
  • 应用场景
    • 资源：下载/加载
    • 主线程逻辑分帧处理
    • 网络通讯

Invoke 和 InvokeRepeating

  • 区别
    • Invoke：单次执行
    • InvokeRepeating：循环执行
  • InvokeRepeating 是定时方法调用，不是协程；不要用协程的停止规则推断它，停用逻辑时可显式调用 CancelInvoke

AssetBundle

  • AssetBundle 的接口
    • BuildPipeline.BuildAssetBundles
  • AssetBundle 的压缩格式
    • LZMA：对 Bundle 整体解压
    • LZ4：按压缩块解压所需内容
    • 不压缩
  • 打包粒度的权衡
    • 粒度大：一个小的修改可能导致大 Bundle 的下载
    • 粒度小：io 比较多
  • 资源冗余打包的剔除
    • 内部资源冗余如何处理：对于 Bundle 内的资源（贴图、材质，Shader），写资源工具创建出来，然后修改原资源的引用关系，最后走统一的打包流程。
    • 外部资源冗余如何处理：获取待打包的资产依赖项进行计算，据此提出，进行独立打包。
  • 资源卸载流程
    • AssetBundle.Unload(true/false)参数的区别
      • true：AB 及 AB load 出来的 Asset 都会被卸载
      • false：仅 AB 会被卸载
    • AssetBundle 中的 Asset 如何卸载
      • Resources.UnloadAsset：卸载指定的 Asset
      • Resources.UnloadUnusedAssets：未被使用的 Asset 均会被卸载
    • Destroy 卸载的是什么
      • 销毁指定的 UnityEngine.Object；不负责自动卸载它引用的所有资源

UGUI

底层

Rebuild

  • 什么情况下触发
    • OnEnable
      • 调用 CacheCanvas，获取父对象的 Canvas 组件
      • 将父对象的 Canvas 组件，注册到 GraphicRegistry
      • SetAllDirty
        • 通知 LayoutRebuilder 布局重建
        • Vertex 顶点信息（SetVerticesDirty）
        • Material 材质（SetMaterialDirty）
    • OnDisable
      • 从 GraphicRegistry 移除 Canvas 注册
      • 通知 LayoutRebuilder 布局重建
    • 当 RectTransform 数值改变时
      • OnRectTransformDimensionsChange
        • 顶点 Dirty
        • 布局 Dirty
    • 父对象改变时
      • OnBeforeTransformParentChanged
        • 从 GraphicRegistry 移除注册
        • 重建布局
      • OnTransformParentChanged
        • 重新获取父对象长得 Canvas，并重新注册在 GraphicRegistry
        • SetAllDirty
    • 应用动画属性后
      • OnDidApplyAnimationProperties
        • SetAllDirty
    • 当画布层次改变时
      • OnCanvasHierarchyChanged
        • 如果 Canvas 改变，重新注册到 GraphicRegistry
  • ReBuild 做了什么
    • Rebuild Layout
      • 计算各元素的位置和大小
    • RebuildGraphic
      • UpdateGeometry 重构网格数据
        • OnPopulateMesh
          • 设置顶点三角形
          • 修改 Mesh 信息
          • 将信息设置到 CanvasRenderer
      • UpdateMaterial 更新材质数据
        • 设置 CanvasRenderer 的材质和纹理
  • 怎么办
    • 动静分离，拆分 Canvas，尽量减少 Graphic Rebuild 的频率
    • 删除不需要的节点和隐藏不用的节点，减少深度排序和 Rebuild
    • 在所属 Canvas 上按需关闭 Pixel Perfect，减少 Layout Rebuild 的频率
    • 设置移动阈值，减少开销
    • Material.SetColor
      • 好处：不会更改网格信息，因此不会有 Rebuild
      • 坏处：因为修改了材质，所以增加了一个 DrawCall

Image 和 RawImage 的区别

  • 共同点
    • 均派生自 MaskableGraphic
  • 不同点
    • Image
      • ISerializationCallbackReceiver：实现序列化和反序列化
      • ILayoutElement：布局元素，调整尺寸
      • ICanvasRaycastFilter：IsRaycastLocationValid 筛选处被射线照射到的图像
    • RawImage
      • 直接显示 Texture，支持 UV 区域设置，不能笼统认为比 Image 更轻量
      • 支持 uvRect 和 SetNativeSize 等接口；实际批次开销需结合纹理和材质检查
      • 非布局元素，不像 Image 一样派生自 ILayoutElement

Event

  • 清除不必要的 Event 监听：
    • CanvasGroup 适时禁止 Interactable
    • 适时禁用 UI 组件上的 RaycastTarget
  • 原因：
    • EventSystem.Update 遍历屏幕中所有 RaycastTarget 为 true 的对象，发射射线并排序，找到最先触发的 UI，抛出事件给逻辑层处理

图集

  • 同一材质，降低 DrawCall，降低内存
  • 不同平台的纹理图集压缩格式
    • And：ETC2
    • iOS：ASTC/ETC2

优化

降 DrawCall

  • 合理划分图集和 Canvas
  • 动静分离
  • 穿透问题
    • 避免图集交叉，中断合批
    • 字体和 UI 尽量不要穿透，字体先于 UI 渲染，中断合批
  • 用 RectMask2D 代替 Mask ：通常可避免模板遮罩的额外绘制，具体收益以 Frame Debugger 为准
    • Mask GPU 模板剔除实现
    • RectMask2D GPU 顶点剔除实现
  • CanvasGroup.alpha = 0 表示视觉透明，不应直接等同于停止全部更新或零 DrawCall；交互需另行控制，绘制收益用 Frame Debugger 检查

降低 OverDraw

  • 避免多个全屏界面重叠
  • 全屏事件点击，单独写继承自 MaskableGraphic 的类，不进行 OnPopulateMesh 顶点处理
  • 全屏界面可以关闭后方的 3D 相机
  • FillCenter 勾选去除
  • 矩形裁剪尽量采用 RectMask2D 替换 Mask：通常可避免模板遮罩的额外绘制，具体收益以 Frame Debugger 为准
  • CanvasGroup.alpha = 0 表示视觉透明，不应直接等同于停止全部更新或零 DrawCall；交互需另行控制，绘制收益用 Frame Debugger 检查

降内存

  • 清除 UI 预设中不必要的资源对象：减少内存和加载耗时
  • 按需关闭 Best Fit 并指定字号；ContentSizeFitter 调整布局尺寸，不能作为自动字号适配的等价替代
  • Image Tiled 平铺模式
    • 原理：接口判断条件会导致大量三角形构建
    • 解决方案
      • 方案 1（适用于无边框、可重复纹理的平铺需求）
        • 不要打到图集里面
        • 不要增加 Border
        • 要选择 Repeat 重复模式
      • 方案 2
        • 使用 RawImage 替代

其他

名词解释

  • DrawCall
    • CPU 准备数据，调用底层渲染接口的过程
    • 影响 CPU
  • OverDraw
    • 单位时间内，单帧单像素被多次渲染
    • 影响 GPU
  • 像素填充率
    • GPU 单位时间内所渲染的像素的数量（单位：MPixels/S）
  • 贴图分辨率
    • 像素密度
  • 纹理填充率
    • GPU 单位时间内所能处理的纹理贴图的数量
  • 显存带宽
    • 显存在单位时间内所能传输的数据的大小

Mono 和 IL2CPP 的区别

  • 原理：
    • Mono：将 C#代码转为 IL 中间代码，由 Mono 运行时执行，常见平台使用 JIT，具体方式受平台约束
    • IL2CPP：将 C#转为 C++，通过各个平台的 C++编译器直接生成机器码
  • Mono 和 IL2CPP 机器码生成的时间一个快一个慢，不能据此判断所有场景的性能高低，应在目标平台测量。IL2CPP 提高了分析成本，但仍可进行原生代码逆向，这不等同于对代码加密，而Mono生成出的项目，是可以通过 ILSpy 反编译出来的。

为什么字体的 BestFit 对内存有影响

  • BestFit 受字体大小动态调整，因此字号大小不一，从而生成出不同字号的 FontTexture，对内存产生影响

为什么 Mask 可能比 RectMask2D 增加 DrawCall

  • Mask 通过模板缓冲区参与裁剪，通常会增加额外的绘制步骤；实际开销应使用 Frame Debugger 测量。
    • 写入模板：遮罩图形写入模板值，子图形通过模板测试限制显示区域。
    • 恢复模板状态：结束该遮罩范围后恢复模板值，具体绘制次数受嵌套和材质影响。

如果运行中将 UGUI 的 Image 对象的 Color 设置为 0，还有 OverDraw

  • 有 DrawCall，也有 OverDraw

非 UI 方向的优化

  • DrawCall
    • 静态批处理
    • 动态批处理
    • Occlusion Culing（遮蔽剔除）
    • Culing Distance（远近剔除）
    • 模型 LOD
    • 相同材质的模型进行合并
  • OverDraw
    • Occlusion Culing（遮蔽剔除）
    • Culing Distance（远近剔除）
    • 模型 LOD
  • 内存
    • Mono 方向
      • 编程语言层面
        • 字串拼接
          • C#：StringBuilder
          • Lua：table.concat
        • 避免容器频繁扩充
          • 通过计算，得到容量大小时直接固定
        • 少在局部变量中 new 引用对象，避免 GC
        • 避免内存碎片，提前大额内存申请
          • Unity 的内存管理方式时非分代非压缩的内存管理方式
        • 结构体可以满足需求的情况下，尽量用结构体取代类
      • 配置表优化
        • C#
          • 打包时，将所有配置文件全部压缩到一个二进制文件内
          • 然后真机模式下读取该二进制流，通过 FileStream 进行字节偏移，以此按需取数据
        • Lua
          • 按需 require
    • Native 方向
      • 美术资源预处理
        • 动画
          • 压缩动画精度并比较误差和资源大小，收益取决于素材
        • 模型
          • Model、Read/Write Enable 关闭
        • 贴图
          • Read/write Enable 逐像素可修改参数
            • 用途：只有开启此项，才可以使用Texture2D.GetPixel接口，获取像素数据
            • 弊端：内存中会保留一份内存的拷贝，占用双倍内存
          • Generate Mipmap
            • 用途：Mipmap 有效降低渲染带宽的压力，提升游戏的渲染效率
            • 弊端：会增加纹理内存，额外增加 33%内存
        • 粒子
          • 按目标设备预算控制贴图、网格面数、粒子数量及屏幕覆盖面积，避免将固定数值作为通用标准
      • 对象池
        • 原理：将对象存储到一个池子里，当需要时再次使用，而不是每次实例化一个对象。
      • AssetBundle
        • 规避 AB 资源打包带来的资源冗余
        • 避免运行时的资源泄漏
          • AB.Unload(false)可能引发 Res 泄露
            • 泄露原因
              • 仅加载了 AB，但是之前 AB 加载出来的 Asset 可能造成泄露。
              • 再次加载 AB，再次 LoadeAsset，此时该 Asset 与上次的 Asset 时两个东西，前者 Asset 和 AB 已经断开连接，后者是一个全新的引用关系。此时出现两份 Asset，造成了 Asset 冗余，即泄露。
            • 解决方式
              • 采用 AB.Unload(true)代替
                • 对 AB 进行智能化管理，实现 AB 引用计数机制：为每个对象采取引用计数管理方法，只有当 AssetBundle 的所有对象都没有使用时，再卸载 AssetBundle。
              • 继续采用 AB.Unload(false)
                • 将 Asset 断开所有对象的引用，调用 Resources.UnloadUnusedAssets。
